# 微信小程序本地交付记录

日期：2026-11-18；分支：`miniprogram`，基于 `95d114a`。范围和非目标见[实施合同](miniprogram-plan.md)，配置和 API 见[小程序说明](../miniprogram/README.md)。

## 已实现

新增原生小程序的登录、看板、首次设置、资产范围历史、记录录入和服务端预览、详情及确认/沟通/删除/更正、记录类型维护、月度总结及确认/入账、协议文件页面。新增 `/api/mini` JSON/Bearer 适配层，调用现有 Accounts、Family 和纯规则；Web 原有 Cookie、来源校验、页面和接口继续保留，数据库无需迁移。

会话使用现有数据库会话模型。UI 失败提示保留原表单，登记/确认/更正重试使用同一提交标识，当前提交期间禁止重复操作。客户端不保存帐号密码，不持有 AppSecret；本地 API 地址与发布域名在 config.js 边界配置。

## 测试证据

- RED：新增 API 测试因缺少 mini-api 模块失败；客户端测试因缺少 api.js 失败。输入测试另观察到空分数被当作零分预览，修复后通过。历史类型选择、自动恢复登录、总结次数名称都有先失败再通过证据。
- `npm test`：116 项通过，包括新增 11 项 API、8 项客户端和 8 项页面行为测试。
- `npm run typecheck`、`npm run format:check`：通过；格式范围加入小程序 JS/JSON/WXSS/WXML。
- `npm run build`：Next.js 默认 Turbopack 生产构建通过，包含 `/api/mini` 路由。
- `npm run test:e2e`：16 条通过（15 条既有 Web 场景，1 条小程序与 Web 真实 HTTP 联调）。
- 聚焦 HTTP 联调：实际小程序页面 JS → 模拟 wx 网络 Adapter → 本机 Next.js HTTP → 隔离 SQLite；Web 登录、读取小程序登记事项并确认；小程序读取确认、反向更正、双方确认、总结、重复入账以及 Web 钱包同步通过。

完整 Web 回归过程中曾出现现有 `Navigation` 组件的 hydration mismatch 控制台提示；该组件本轮未改动，另出现输入属性 hydration 提示及页面切换时一次流写入错误，全部 16 条功能断言最终通过。此提示与微信原生编译无关，保留为后续 Web 排查项。

Next.js 启动/构建报告当前版本存在已知安全漏洞并提示升级，首次运行因此退出，按工具提示原命令重试后通过。本轮没有升级依赖；生产发布前应单独处理该提示。

## 验收边界

当前没有注册 AppID，本机未安装微信开发者工具。项目使用游客 AppID 与本地 API 地址；原生 WXML/WXSS 编译、视觉检查、真机导航和真实协议文件打开仍待开发者工具与设备验收，不宣称已完成这些检查。

没有修改或部署生产服务器，也没有连接正式数据库、上传体验版或提交微信审核。生产 Web 目前不会自动拥有新增小程序接口；发布前需要部署本分支后端、配置合法 HTTPS 请求/下载域名、替换 AppID、核实主体/类目/备案要求，并完成微信端验收。
